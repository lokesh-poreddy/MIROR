# MIROR V14 Production Completion

V14 hardens the four production blockers: admin security, durable enquiry handling, canonical SEO, and project media governance.

## 1. Admin security
- `/admin`, `/admin/evidence`, and `/admin/media` are protected by `src/app/admin/layout.tsx`.
- Credentials are supplied through server-only environment variables.
- Passwords are verified with PBKDF2-SHA256; sessions are HMAC-signed and stored in an HttpOnly, SameSite cookie.
- Admin APIs independently verify the session.
- The existing V10 unsigned/base64 session helper is no longer part of the V14 path.

Generate the password hash with:

```bash
node tools/generate-admin-password-hash.mjs 'A-strong-password-of-12-or-more-characters'
```

Create a random session secret using a password manager or equivalent cryptographically secure generator; do not commit it.

## 2. Durable enquiries
The public enquiry endpoint now persists first and notifies second. This changes the contract from “logged on the server” to “stored in PostgreSQL/Supabase before a success response”.

Apply `db/schema-v14-enquiries.sql` to the production Supabase/PostgreSQL database. The table is protected with RLS and no public/authenticated grants. The server uses the secret key only.

Email notification is optional but durable state records `sent`, `failed`, or `not_configured`.

## 3. SEO / canonical deployment
Set `NEXT_PUBLIC_SITE_URL` to the real deployed origin. The code intentionally does not invent Miror's final public domain.

`metadataBase`, canonical metadata, complete public route sitemap coverage, and `/robots.txt` are generated by the App Router. Sensitive `/admin`, `/admin-login`, `/system`, and `/api` routes are excluded from crawling.

Delete the legacy `public/robots.txt` after applying this bundle so there is one source of truth.

## 4. Project media governance
`src/data/project-media.ts` is the publication registry. Empty registries render an original engineering-style placeholder rather than fake/stock project photography.

Add an approved asset only after client/company approval and rights confirmation, for example:

```ts
const registry = {
  "revasa-la-valora": [
    {
      type: "image",
      src: "/media/projects/revasa-la-valora/rcc-execution-01.webp",
      alt: "RCC execution work at the Revasa La Valora site",
      credit: "Miror Constructions & Consultancy",
      license: "Company-owned / approved for website publication",
      approved: true,
    },
  ],
};
```

Do not insert an image just because it visually matches a project. Every asset needs a traceable publication right.

## 5. Next config
V14 explicitly sets `partialPrefetching` to remove the Next.js warning and adds a conservative CSP/HSTS baseline. Review the CSP if analytics, maps, fonts, or external media providers are added later.

## 6. Apply to GitHub
The current GitHub integration rejected write operations with HTTP 403 during V14 creation. Apply the files from this bundle to the existing `main` branch, then run:

```bash
npm ci
npm run validate:production
npm run typecheck
npm run build
```

Before a production deployment, configure the environment variables and apply the database schema. Do not publish `.env` files or secret keys.
